# spec: 貸出の延長

- 元の intent: [docs/intents/loan-extension.md](../intents/loan-extension.md)（開発部）
- 状態: 受け入れ済み（講師が用意した spec で、2周目はここから Build に入る）
- 適用した Skill: secure-api

## 要件

- R1. 借り手は、返却していない貸出の返却期限を、**現在の返却期限から**7日延ばせる（今日からではない）
- R2. 延長は1回まで。一度延長した貸出は、もう延長できない
- R3. 返却期限を過ぎた貸出は延長できない。返却期限の当日は期限内として延長できる
- R4. 借り手本人だけが延長できる。本人以外の利用者（管理者を含む）には、その貸出が存在するかどうかも分からない

## 設計

- 既存の貸出 API に、延長のエンドポイントを追加する。既存の認証（Bearer トークン）の後ろに置き、返却 API と同じ形にする
- 延長の規則（本人か、返却済みか、期限超過か、上限か）はドメイン関数で判定し、ルートは結果を HTTP の応答に変換するだけにする。延長できない理由が複数あるときは、本人でないことを最優先にする
- 貸出がすでに持っている返却期限と延長回数を使う。今日の日付はサーバーの時計から求め、クライアントから受け取らない
- 延長の成否（成功、本人以外の拒否、それ以外の失敗）を監査ログに残す。監査ログに個人情報は記録しない。応答で分かる借り手の情報は ID と氏名だけにする
- 予約や延長の履歴は新しく持たない

## intent の制約をどう満たすか

| 制約 | 満たし方 |
|---|---|
| 延長は1回まで。延長期間は7日 | R1、R2 |
| 期限超過中は延長できない | R3。期限の当日は期限内として扱う |
| 延長できるのは借り手本人だけ。管理者も代理で延長しない | R4。本人かどうかをドメイン関数で判定する |

## intent で解決しない問い

- 次に借りたい人の予約がある場合に延長を断るか → 予約機能がないので今回は扱わない

## 懸念点

1. 本人以外に「権限がない」と返すと、他人の貸出 ID が有効かどうかが分かってしまう。貸出が存在しない場合と同じ応答にする（R4）。担当: テックリード
2. 延長すると、自分の貸出の一覧（Day1 の機能 A）に出る返却期限も延長後の値に変わる。総務部の台帳と食い違わないよう、延長の記録は監査ログで確かめられることを総務部に伝える。担当: PO
3. 延長の取り消しと、管理者による延長回数のリセットは今回扱わない。運用で必要になったら別の intent にする。担当: PO
