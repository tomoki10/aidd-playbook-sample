# Plan B2: 貸出延長 API の追加

## Approach

1. 借り手が自分の貸出を延長する API を、既存の認証の後ろに追加する
2. 延長できるかの判定は B1 のドメイン関数に任せ、結果を Issue の応答とエラーコードの一覧どおりに返す
3. 延長の成否を監査ログに残し、応答の借り手は ID と氏名だけにする

## Risks

- 延長の規則をルート側にも書くと、B1 と判定が二重になり、食い違ったときに気づけない
- 本人以外に「権限がない」と返すと、他人の貸出 ID が有効かどうかが分かってしまう

## Verification

- Issue の受入テストの観点と期待値を、実装と同じ PR でテストにし、テスト名に R 番号を付ける。B1 のドメイン関数は差し替え、HTTP への変換だけを確かめる
- B1 のマージ後に main を取り込み、lint、typecheck、test がすべて通ることを確認する
