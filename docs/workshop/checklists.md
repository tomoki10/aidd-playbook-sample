# 承認ゲートのセルフレビュー用チェックリスト

研修は個人ワークなので、承認も自分で行います。役を切り替えて、次の項目を確かめてから PR をマージします。実際のチームでは、括弧内の役の人が承認します。

## intent.md（PO）

- [ ] 問題が「誰が・どんな場面で・何に困っているか」で書かれている
- [ ] 期待する結果が、解決策ではなく「できるようになること」で書かれている
- [ ] 影響を受ける利用者とシステムが挙がっている
- [ ] 制約（権限、期限、やってはいけないこと）が書かれている
- [ ] 決めていないことが「未解決の問い」に残っている

## spec.md（PO、テックリード）

- [ ] intent.md へのリンクがあり、intent の制約を満たしている
- [ ] 受入条件が、テストに書ける形（入力と期待する出力）になっている
- [ ] 並行に実装するタスクの間のインタフェース（関数のシグネチャ、API の入出力）が決まっている
- [ ] secure-api の観点（認証・認可、入力検証、個人情報、監査ログ、エラー）に答えている
- [ ] 範囲外が書かれている

## plan.md（エンジニア）

- [ ] spec と Issue へのリンクがある
- [ ] 触るファイルと触らないファイルが分かれている
- [ ] spec で決めたインタフェースを変えていない
- [ ] 確かめ方（実行するコマンド）が書かれている

## 実装の PR（レビュアー）

- [ ] plan.md のコミットが実装のコミットより前にある
- [ ] `npm run lint && npm run typecheck && npm test` が通る
- [ ] spec の受入条件ごとにテストがある
- [ ] 差分が plan の「触るファイル」に収まっている
