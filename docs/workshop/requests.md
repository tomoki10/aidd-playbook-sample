# 講師用: ワーク1で起票する要望

ワーク1の最初に、この要望を `.github/ISSUE_TEMPLATE/request.yml`（要望テンプレート）で自分のリポジトリに起票します。Issue の画面から「New issue」→「要望」を選び、各欄に次の文をそのまま貼ります。

`gh` で起票する場合は次のコマンドを使います。

```bash
gh issue create --title "[要望] 返却期限を過ぎた貸出を一覧で見たい" --label intent --body-file docs/workshop/request-overdue-loans.md
```

## 機能 A: 返却期限を過ぎた貸出の一覧

- タイトル: `[要望] 返却期限を過ぎた貸出を一覧で見たい`
- 起案者（部署）: 総務部

### 困っていること

返却期限を過ぎても返ってこない備品が増えている。毎週月曜に貸出台帳を見て督促の連絡をしているが、期限切れの貸出を探すだけで30分かかる。見落としもあり、半月以上返ってこなかった PC があった。

### こうなってほしい

期限を過ぎた貸出を一覧で見たい。何日過ぎているかと、誰に連絡すればよいかが分かるとうれしい。

### 補足

督促は総務部だけが行う。来月の棚卸しまでに使えるようにしたい。

## 講師メモ

- 「誰に連絡すればよいか」の一文は、借り手のメールアドレスや電話番号を API で返す設計を誘う。ワーク2で `secure-api` Skill を有効にすると、spec の段階で「連絡先は社員名簿で引けるので、API は借り手の ID と氏名だけを返す」「総務部（管理者）だけが見られる」といった懸念が挙がる
- 「総務部だけが行う」は認可（管理者のみ）の根拠になる。intent の「制約」に書かれているかを PO 役のセルフレビューで確かめさせる
- 期限当日を期限超過に含めるかは、intent の「未解決の問い」に残すか spec で決めさせる。記入例の spec（`stage-2-done`）では「当日は含めない」にしている
