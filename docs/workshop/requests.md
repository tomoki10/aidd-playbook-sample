# 講師用: ワーク1で起票する要望

ワーク1の最初に、この要望を `.github/ISSUE_TEMPLATE/request.yml`（要望テンプレート）で自分のリポジトリに起票します。`gh issue create --web` で Issue の画面を開き、「要望」を選んで、各欄に次の文をそのまま貼ります。

画面を使わずに起票する場合は、次のコマンドでも同じ内容になります。

```bash
gh issue create --title "[要望] 空いている備品と自分の貸出を確かめたい" --label intent --body-file docs/workshop/request-borrowing-status.md
```

## 機能 A: 備品の空き状況と自分の貸出の確認

- タイトル: `[要望] 空いている備品と自分の貸出を確かめたい`
- 機能名（`docs/intents/` と `docs/specs/` のファイル名）: `borrowing-status`

### 困っていること

「いま空いているノート PC はあるか」「自分が借りている備品の返却期限はいつか」という問い合わせが、毎日10件ほど総務部に来る。そのたびに貸出台帳を開いて答えていて、1日30分ほどかかっている。

### こうなってほしい

社員が自分で、空いている備品を種類で探せて、自分が借りているものと返却期限を確かめられるようにしたい。

### 起案者（部署）

総務部

### 補足

ほかの社員が何を借りているかは見せたくない。来月の棚卸しまでに使えるようにしたい。

## 講師メモ

- 「ほかの社員が何を借りているかは見せたくない」は、認可（本人の貸出だけを返す）と個人情報の最小化（備品の一覧に借り手を含めない）の根拠になる。intent の「制約」に書かれているかを PO 役のセルフレビューで確かめさせる
- 「空いている」の定義は、intent の「未解決の問い」に残すか spec で決めさせる。記入例の spec（`stage-2-done`）では「返却されていない貸出がない」とし、返却期限を過ぎていても返却されるまでは貸出中として扱う
- 「自分が借りているもの」に返却済みの貸出を含めるかも、spec で決めさせる。記入例では返却前の貸出だけにしている
- ワーク2で `secure-api` Skill を有効にすると、spec の段階で「本人は認証から特定し、利用者 ID をクライアントから受け取らない」「備品の一覧に借り手の情報を含めない」といった懸念が挙がる
